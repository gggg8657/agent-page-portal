# 내 작업 보관함 API

하나의 `portal.db`에서 로그인 계정 ID로 `work_items`, `work_versions`, `work_sync`를 분리한다. 관리자도 새로 저장하는 작업은 계정별이다. 요청 본문의 uid/사용자 헤더로 다른 계정의 작업을 지정할 수 없다.

- `GET /api/workspace?tool=&q=&view=active|starred|trash&limit=50&offset=0`: 계정별 목록·제목 검색·페이지.
- `GET /api/workspace/<id>[?revision=1]`: 저장 내용과 과거 버전. 다른 계정의 id는 404.
- `POST /api/workspace/save {tool,title,payload,id?,revision?}`: 새 저장. 기존 저장을 바꿀 때 현재 revision 필수, 충돌 시 409. 저장본은 버전별로 보존.
- `POST /api/workspace/modify {id,action,title?,starred?}`: rename/star/archive/restore. 보관함의 숨김은 원본 도구 결과를 삭제하지 않는다.
- `POST /api/workspace/sync {tool?}`: 도구 22개의 기존 이력 목록을 서버가 사용자 서명으로 조회하고 계정별 DB에 저장. 큰 파일은 원래 도구에 유지. 일부 도구가 꺼져 있으면 sources에서 실패를 표시하고 기존 DB 사본은 유지.

원본 이력의 상세 JSON은 보관함에서 해당 작업을 열 때 조회해 DB 사본을 갱신한다. 원본 도구가 꺼졌거나 삭제됐으면 마지막으로 저장된 사본과 offline=true를 반환한다. 처음 가져온 목록에는 목록 메타데이터만 있을 수 있다. 모델 호출이나 결과 재생성은 하지 않는다.

새 저장 화면의 form-v1 payload는 텍스트/선택 입력·현재 보이는 결과 텍스트·첨부 파일 이름·다음 단계 메모다. 비밀번호/숨김/토큰/API-key 입력은 수집하지 않는다. 실제 첨부 파일은 복원하지 않으므로 다시 선택해야 한다. 영상·3D·이미지 파일은 기존 도구의 작업 이력에서 연다.

기존 코드에서 관리자 도구 데이터는 owner 공용 공간이다. 해당 이력은 `legacy_shared=true`로 명시한다. 과거 공용 파일을 특정 계정 것으로 임의 재분류하거나 옮기지 않는다. 일반 계정 이력은 기존 도구의 사용자별 경로 및 서명 관문으로 제한된다.

사주(공용 계정 프로필), 파동이(실행 명령), 주간보고(부서별 제출·취합), 숨긴 persona는 일반 이력 import 대상이 아니다. 이 도구에서도 현재 입력/텍스트는 ‘작업 저장’으로 계정 보관함에 저장할 수 있다. 업무별 기존 데이터 권한을 바꾸지 않는다.

다음 에이전트에 넘길 때 작업 상세의 ‘에이전트 인수인계 내려받기’를 쓴다. 계정 데이터가 포함된 파일이므로 사용자가 선택한 대상에게만 전달한다. 서버가 자동으로 외부에 전송하지 않는다.
